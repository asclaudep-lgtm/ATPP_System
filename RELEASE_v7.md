# ATPP_System v7 — Release Notes

**Дата:** 2026-05
**Базовая версия:** v6 (production tracking + barcode + issues)

---

## Главное

В v7 у системы появились **два больших улучшения**:

1. **Новый UI для технолога**: вкладка «Группа» (дерево деталей) + вкладка «КТП»
   (карточка детали с вариантами ТП). Подробнее ниже.
2. **Контроль производства в цехе**: окно «Операционный маршрут детали»,
   интеграция сканера штрих-кода, поиск «Где сейчас деталь?» по F3.

## Workstream A — UI: Группа / КТП

### Дерево «Группа»
- Иерархия групп / подгрупп / деталей (без устаревшего префикса «Агрегаты»).
- В корне виртуальные секции:
  - **🆕 Без ТП** — детали, по которым технолог ещё не создал ни одного ТП.
  - **🟡 На согласовании** — ТП в статусе REVIEW.
  - **🔁 На доработке** — ТП в статусе REWORK (отклонено ОТК).
  - **📋 Шаблоны** — ТП с признаком `is_template=True`, можно клонировать
    на любую деталь.
- Поиск (Ctrl+F) фильтрует дерево вместе с подгруппами.
- Drag-and-drop: перетягиваем деталь между группами.
- Контекстные меню: переименовать/создать подгруппу/удалить.

### Вкладка «КТП · обозначение наименование»
Открывается двойным кликом на деталь.

- Шапка детали: обозначение + наименование + материал/масса/класс точности
  (только для чтения).
- Слева список **вариантов ТП**:
  - бейдж статуса 🟢 Утверждён · 🟡 На согл. · ⚪ Черновик · 🔁 Доработка · ⚫ Архив;
  - звезда «⭐ По умолчанию» — этот вариант мастер видит в наряде первым;
  - имя варианта = `execution_variant` (например, «Универсальное оборудование»,
    «Обработка ЧПУ»).
- Справа — встроенный редактор маршрутки (операции, переходы, материалы,
  расчёт себестоимости, документы): тот же редактор, что и раньше, со всеми
  горячими клавишами и функциями.
- Кнопки:
  - **+ Новый ТП** — создаёт пустой вариант;
  - **🗐 Копия** — клонирует текущий вариант со всеми операциями/переходами;
  - **Переименовать** — меняет имя варианта;
  - **⭐ По умолчанию** — отмечает вариант как основной (атомарно: предыдущий
    «по умолчанию» сбрасывается);
  - **🔀 Сравнить два** — открывает диалог `TPCompareDialog`: две таблицы
    бок-о-бок, подсветка различий (жёлтый — отличается, зелёный — только слева,
    красный — только справа), синхронная прокрутка;
  - **Удалить** — мягкое удаление (`is_deleted=True`).
- Если у детали нет ни одного ТП — большой плейсхолдер с зелёной кнопкой
  «+ Создать первый вариант».

### QSettings
- Положение разделителя «дерево / редактор» сохраняется per-user.

### Изменения в БД
В таблицу `tech_processes` добавлены 2 поля (миграция автоматическая):

```sql
ALTER TABLE tech_processes ADD COLUMN is_default_for_product BOOLEAN NOT NULL DEFAULT 0;
ALTER TABLE tech_processes ADD COLUMN is_template            BOOLEAN NOT NULL DEFAULT 0;
```

## Workstream B — Производство

### Окно «Операционный маршрут детали» (RouteWindow)
Открывается:
- двойным кликом на наряде (для нарядов в статусе после RELEASED);
- сканером штрих-кода: ввести `WO-XXXX-NNNN` — открывается маршрут;
- из диалога «Где сейчас деталь?» (F3).

В окне:
- Шапка: № наряда, штрих-код Code128 (картинкой), деталь, ТП, кол-во, статус.
- Баннер активных проблем (красный, если есть открытые `ProductionIssue`).
- Таблица всех `RouteStep` по всем партиям: №оп / партия / название /
  цех / статус / исполнитель / время старта-финиша / брак.
- Журнал событий (`ProductionEvent`) хронологически.
- Кнопки:
  - **▶ Старт операции** — `start_operation(item_id, op_id, worker_id)`;
  - **■ Финиш операции** — `finish_operation(item_id, op_id, qty_ok, qty_scrap)`.

### Сканер штрих-кода (ItemsTab)
Логика обработки:

1. Если ввели код наряда (`WorkOrder.barcode`) → открывается RouteWindow.
2. Иначе — ищется партия (`WorkOrderItem.barcode`), как было в v6.

### Поиск «Где сейчас деталь?» (WhereIsPartDialog)
Глобальный хоткей **F3** теперь открывает этот диалог.

Ввод: обозначение / наименование / штрих-код. Результат — таблица активных
нарядов (RELEASED, REGISTERED, IN_PROGRESS, ON_HOLD) со столбцами:

| Наряд | Штрих-код | Деталь | ТП | Кол-во | Текущая операция | Цех | Статус | % готово |

Двойной клик по строке → открывает RouteWindow для этого наряда.

### МТП в формате УЗГА (xlsx) — v7.5
- Генератор работает **поверх оригинального шаблона УЗГА-Инжиниринг**
  (resources/MTP_УЗГА_template.xlsx), не ломая рамок/штампов/мерджей.
- Штрих-код Code128 встроен в верхний левый угол шапки.
- Опция **«Свернуть промежуточные»**: удаляет все промывочные/контрольные,
  оставляя только финальную контрольную (~24 операции → 11).
- Кнопка «📋 МТП (xlsx)» на вкладке «Наряды».

  в новую вкладку КТП и работает ровно как раньше.
