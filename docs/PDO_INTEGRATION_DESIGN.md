## 1. Два мира, которые нужно связать

### Мир A: Предпроизводственная подготовка (реальные документы УЗГА)

```
ПЭУ → ОМТС → Тех.отдел → Зам.Тех.Дир → Цех
 │       │        │            │
 Заявка  Материал? КД?         Служебная записка
                    Возможно?    на изготовление
```

**Существующие модели ATPP для этого:** `ProductionOrder`, `PDOHandoff`, `MTPSignoff` (созданы в v14).

**Чего не хватает:** `ServiceMemo` (служебная записка), `NomenclatureItem` (позиция с флагом «возможно/нет»), связь с `MaterialBatch`.

### Мир B: Производство (уже есть в ATPP)

```
Технолог → Мастер → Рабочий → ОТК
   │         │         │        │
   ТП      Партии   Операции  Приёмка
```

**Существующие модели ATPP для этого:** `TechProcess`, `WorkOrder`, `WorkOrderItem`, `RouteStep`, `ProductionEvent`, `ProductionIssue`.

**Это работает.** Трогать не нужно.

## 2. Схема интеграции

```
                        ProductionOrder
                       (единый трекер)
                             │
              ┌──────────────┼──────────────┐
              ↓              ↓              ↓
        NomenclatureItem  ServiceMemo   WorkOrder
        (что делаем)     (записки)     (наряд в цех)
              │              │
              ↓              
        MaterialBatch
        (материал от ОМТС)
```

**ProductionOrder** — центральная точка. Один заказ связывает:
- **NomenclatureItem[]** — позиции номенклатуры (обозначение, наименование, кол-во, КД, материал, возм.изготовл.)
- **ServiceMemo[]** — служебные записки (проработка ОМТС, изготовление Зам.Тех.Дир)
- **WorkOrder** — наряд в цех (создаётся ПОСЛЕ всех утверждений)
- **MaterialBatch** — связь с партией материала от снабжения

### 3.2. Новая модель: NomenclatureItem

```python
class NomenclatureItem(Base):
    """Позиция номенклатуры к изготовлению."""
    __tablename__ = 'pdo_nomenclature'

    id = Column(Integer, primary_key=True)
    order_id = Column(ForeignKey('production_orders.id'))
    designation = Column(String(100))    # Обозначение детали
    name = Column(String(200))           # Наименование
    qty = Column(Integer)                # Количество
    product_id = Column(ForeignKey('products.id'), nullable=True)
    tech_feasible = Column(Boolean, nullable=True)  # + / - / None(не проверено)
    kd_ready = Column(Boolean, default=False)       # КД готово
    material_name = Column(String(200))  # Требуемый материал
    material_batch_id = Column(ForeignKey('material_batches.id'), nullable=True)
    tech_notes = Column(Text)            # Тех.указание
```

### 3.3. Новая модель: ServiceMemo

```python
class ServiceMemo(Base):
    """Служебная записка (У=указание, П=приказ)."""
    __tablename__ = 'pdo_memos'

    id = Column(Integer, primary_key=True)
    order_id = Column(ForeignKey('production_orders.id'))
    memo_type = Column(String(20))       # 'У' (указание) или 'П' (приказ)
    memo_number = Column(String(40))     # "356п от 03.08.2023г."
    from_dept = Column(String(60))       # ОМТС / Зам.Тех.Дир
    issued_by = Column(ForeignKey('users.id'))
    issued_at = Column(DateTime)
    content = Column(Text)               # Текст записки
    pdf_path = Column(String(500))       # Путь к PDF-оригиналу
```

## 4. Обновлённый статус ProductionOrder

```
Черновик
  → ОМТС_ПРОРАБОТКА      (ОМТС проверяет материал)
    → ТЕХ_ОТДЕЛ           (тех.отдел: КД, тех.указание, возм.изготовл.)
      → ЕСТЬ_НЕВОЗМОЖНЫЕ  ← если хотя бы одна позиция с minus
      │   → ОТКАЗ_ТЕХ     ← заказ невыполним
      → ЗАМ_ТЕХ_ДИР       (утверждение, служебная записка на изготовление)
        → ПЕРЕДАН_В_ЦЕХ   ← здесь создаётся WorkOrder
          → В_РАБОТЕ      ← существующий производственный процесс
            → ЗАКРЫТ
```

## 5. Пользовательский интерфейс

### Канбан-доска (6 колонок, обновлённые названия)

| Колонка | Кто работает |
|---|---|
| 📥 Принят | ПЭУ |
| 📦 ОМТС (проработка) | Снабжение |
| 🔧 Тех.отдел | Технолог |
| ✍ Утверждение | Зам.Тех.Дир |
| 🏭 В цехе | Мастер / Рабочий |
| ✅ Закрыт | ОТК |

### Карточка заказа (обновлённая)

Вместо текущих полей — отображать:
- Номер заказа + тип ВС + заказчик
- Таблица позиций номенклатуры с флажками: КД ✓/✗, Материал ✓/✗, Возм.изготовл. +/−
- Цепочка служебных записок (ОМТС → Зам.Тех.Дир)
- Связанный наряд (WorkOrder), если передан в цех

### Ключевое действие на каждом этапе

| Этап | Действие | Результат |
|---|---|---|
| ПЭУ | «Создать заказ» | ProductionOrder + NomenclatureItems |
| ОМТС | «Выпустить записку на проработку» | ServiceMemo (type='У') |
| Тех.отдел | «Отметить КД», «Указать материал», «Возм.изготовл. +/−» | NomenclatureItem обновлён |
| Тех.отдел | Если все позиции «+» → «Передать на утверждение» | Статус → ЗАМ_ТЕХ_ДИР |
| Зам.Тех.Дир | «Выпустить записку на изготовление» | ServiceMemo (type='П') |
| Зам.Тех.Дир | «Утвердить и передать в цех» | Создаётся WorkOrder |

## 6. Что НЕ нужно менять

| Компонент | Почему |
|---|---|
| WorkOrder / RouteStep | Работает как есть. PDO создаёт WorkOrder на шаге «передать в цех» |
| Workflow (ApprovalSignature) | Работает для утверждения ТП. Не смешивать с утверждением заказа |
| TPEditor | Технолог работает с ним независимо от PDO |
| ProductionWidget | Мастер работает с ним после получения наряда |
| MaterialBatch | Уже есть! Использовать для отслеживания материала |

## 8. Итог

**Главный принцип:** PDO — это ПРЕДПРОИЗВОДСТВЕННЫЙ конвейер.
Он подготавливает всё необходимое (КД, материал, разрешения) и ТОЛЬКО ПОТОМ
создаёт WorkOrder. Существующий производственный процесс не меняется.

**Ключевое отличие от текущей реализации:** добавляется ОМТС (снабжение)
как полноправный этап и появляется проверка «возможно ли изготовить»
на уровне каждой позиции номенклатуры.
