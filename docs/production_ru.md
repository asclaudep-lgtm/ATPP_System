# Модуль «Производство» — руководство пользователя

Назначение модуля — отслеживать прохождение деталей по производству:
от передачи ТП технологом до закрытия наряда. Поддерживается
многопользовательская работа из локальной сети, штрих-коды (Code128) для
быстрой идентификации партий, журнал событий (audit) и система пометок
о проблемах для мастеров.

---

## 1. Кто что делает (роли)

| Роль          | Что делает                                                            |
|---------------|-----------------------------------------------------------------------|
| `technologist` | передаёт утверждённый ТП в производство → создаёт наряд (WorkOrder). |
| `master`      | регистрирует наряд, разбивает на партии, ведёт операции, открывает/закрывает проблемы. |
| `worker`      | стартует/завершает операции по своей партии, сообщает о проблемах.    |
| `qc`          | приёмка по последней операции, открывает проблемы качества.          |
| `admin`       | имеет права всех ролей.                                              |
| `user`        | только просмотр.                                                     |

Назначить роль можно через **Сервис → Управление пользователями…** (только админ).

---

## 2. Как открыть модуль

В главном окне: **Производство → Панель «Производство»…** (Ctrl+Shift+P).

Откроется вкладка с четырьмя разделами:

- **Наряды** — все производственные задания.
- **Партии (WIP)** — что сейчас находится в работе на каждом участке;
  здесь же сканер штрих-кодов и кнопки «Начать / Завершить операцию».
- **Проблемы** — открытые и закрытые проблемы, действия мастера/технолога.
- **Сводка** — мини-отчёты: WIP по участкам и количество проблем по типам.

---

## 3. Сценарий работы технолога

1. Утверждает ТП в обычном workflow (DRAFT → APPROVED).
2. Открывает ТП и нажимает **Производство → Передать активный ТП в производство…**
   (или открывает панель «Производство» → вкладка **Наряды** → кнопка
   *Передать ТП в производство…*).
3. В диалоге указывает:
   - количество (всего, шт.),
   - заказ (опционально),
   - приоритет (0–9),
   - срок (опционально),
   - примечание.
4. После подтверждения создаётся **наряд** в статусе *Передан в производство*.
5. Мастер увидит наряд в своей вкладке **Наряды**.

> Если в ТП не добавлены операции — система не даст зарегистрировать наряд.

---

## 4. Сценарий работы мастера

### 4.1 Регистрация наряда

1. На вкладке **Наряды** выбрать наряд в статусе «Передан в производство».
2. Нажать **Регистрация наряда…**.
3. Указать:
   - **Начальный участок** — куда поступает партия (по умолчанию это «Склад»).
   - **Разбивка партий**:
     - оставить пустым / указать `100` → одна партия 100 шт.;
     - `50,50` → две партии по 50 шт.;
     - `1,1,1,...` → единичная маркировка (каждая деталь — отдельная партия).
4. Нажать **Зарегистрировать**. Система:
   - создаёт партии (`WorkOrderItem`),
   - выдаёт каждому штрих-код (Code128, формат `ATPP-WI-<id>-<rand6>`),
   - формирует **маршрут** партии (RouteStep) по операциям ТП,
   - наряд переходит в статус *Зарегистрирован*.

### 4.2 Печать ярлыков со штрих-кодами

1. Открыть вкладку **Партии (WIP)**.
2. Выбрать партию.
3. **Штрих-код / ярлык…** → открывается окно с PNG-штрих-кодом и подписью
   (серийник партии, наряд, деталь, количество).
4. Кнопка **Сохранить PNG…** — выгружает картинку для печати на любом
   принтере (Word/Excel/прямая печать в Paint).

### 4.3 Сопровождение работ

- **Начать операцию**: партия выделена → кнопка *Начать операцию*. Меняется
  статус операции на *Выполняется*, партия — *В работе*.
- **Завершить операцию…**: спрашивает количество годных и в брак, затем —
  на какой участок передавать партию (если есть следующая операция). Если
  это последняя операция — наряд закрывается автоматически (статус *Завершён*).
- Брак на каждой операции суммируется на партии и в наряде.

> Защита от одновременных правок: если двое мастеров одновременно завершают
> одну и ту же партию, второй получит ошибку «партия изменена другим
> пользователем» — это означает, что его данные устарели. Нужно обновить
> список и повторить.

### 4.4 Сканер штрих-кода

В верхней строке вкладки **Партии (WIP)** есть поле «Сканер / поиск».
Любой обычный USB-сканер штрих-кодов работает как клавиатура: курсор
ставится в это поле, мастер сканирует ярлык — система автоматически
выделяет нужную партию, переключает фильтр на её участок и можно сразу
жать **Начать операцию** / **Завершить операцию…**.

Поле также понимает:
- штрих-код целиком (`ATPP-WI-42-AB12CD`),
- серийник партии (`WO-2025-0001/01`),
- идентификатор партии (`42`).

## 5. Проблемы в производстве (пометки мастера)

Если мастер не может продолжить работу, он:

1. На вкладке **Партии (WIP)** выбирает партию.
2. Нажимает **Сообщить о проблеме…**.
3. Указывает:
   - **Тип**: «Нет материала» / «Нет инструмента» / «Вопрос по КД» /
     «Проблема с оборудованием» / «Вопрос ОТК» / «Прочее».
   - **Серьёзность**: Низкая / Средняя / Высокая / Блокирующая.
   - **Заголовок** (одна строка) и подробное описание.
   - **Ответственный** — кому адресовать (опционально).
   - **Блокирует производство** — если включить, наряд переходит в статус
     *Приостановлен* (ON_HOLD) до закрытия проблемы.

Все проблемы видны на вкладке **Проблемы** — фильтр «Открытые / закрытые / все».
Закрытие проблемы — кнопка **Закрыть проблему…**, нужно описать, как
именно она была решена. Если это была единственная блокирующая проблема —
наряд автоматически возобновится (вернётся в IN_PROGRESS / REGISTERED).

> Закрывать проблемы могут роли `admin / master / technologist / qc`.

## 6. Журнал событий

Все действия сохраняются в таблице `production_events` с указанием:
- кто (пользователь),
- когда (точное время),
- что (тип события: RELEASED / REGISTERED / STARTED / FINISHED / MOVED /
  ITEM_DONE / WO_DONE / WO_ON_HOLD / WO_RESUMED / ISSUE_OPENED /
  ISSUE_ACK / ISSUE_CLOSED),
- по какой партии / наряду / операции / участку.

Это позволяет в любой момент построить отчёт: «что сделал такой-то мастер
с 10:00 до 18:00», «сколько операций по такому-то наряду заняли больше
4 часов», «полная история партии WO-2025-0017/03».

---

## 7. Базовые отчёты

Вкладка **Сводка** в панели «Производство»:

- **WIP по участкам** — сколько партий и штук сейчас на каждом участке,
  сколько из них в работе, сколько ожидают.
- **Открытые проблемы по типам** — группировка по типу проблемы и
  отдельно — сколько блокирующих.

Для глубоких отчётов (по периоду, по сотруднику, по конкретному наряду)
вся информация лежит в БД в обычных таблицах SQLAlchemy и может быть
выгружена через **Сервис → Аналитические отчёты…** или внешним SQL-клиентом
(`pgAdmin`, DBeaver и т.п.).

---

## 8. Производственные участки

Участки сидируются автоматически при первом запуске:
- **WH** — Склад,
- **TURN1** — Токарный участок 1,
- **MILL1** — Фрезерный участок 1,
- **ASSY** — Слесарно-сборочный,
- **QC** — ОТК.

Для добавления / редактирования участков можно либо
- внести изменения SQL-запросом в таблицу `workshops` (через DBeaver/pgAdmin),
- либо создать отдельный диалог-справочник (опциональное расширение).

Каждому участку можно назначить мастера (поле `master_user_id`).

## 9. Архитектура (для админов)

Модели находятся в <path>database/models.py</path>:
- `Workshop` — справочник участков
- `WorkOrder` — наряд
- `WorkOrderItem` — партия (имеет `version` для optimistic-lock)
- `RouteStep` — точка маршрута (один шаг = одна операция для одной партии)
- `ProductionEvent` — универсальный журнал
- `ProductionIssue` — проблема

Бизнес-логика — <path>modules/production.py</path>. Все методы принимают
сессию и работают атомарно. Для работы по сети ничего особенного делать
не нужно: при использовании PostgreSQL (см. <path>docs/network_setup_ru.md</path>)
несколько ПК работают одновременно — конфликты обрабатываются на уровне
БД (MVCC) + optimistic lock на партиях.

## 10. Часто задаваемые вопросы

**Можно ли вернуть партию назад на предыдущую операцию (доработка)?**
Сейчас — только через закрытие операции в брак и создание новой партии.
В следующих версиях планируется явный «возврат на доработку» (статус REWORK
у RouteStep).

**Что делать, если штрих-код порвался / стёрся?**
Откройте партию через серийник в поле «Сканер / поиск» и распечатайте
новый ярлык (кнопка *Штрих-код / ярлык…*). Сам штрих-код у партии не меняется.

**Как отозвать наряд (ошибочно передан)?**
Сейчас — только админом через SQL: `UPDATE work_orders SET status='CANCELED' WHERE id=...`.
В следующей версии будет кнопка «Отменить наряд» в UI.

**Можно ли вести единичный учёт (каждая деталь — свой штрих-код)?**
Да, при регистрации указать разбивку `1,1,1,...` (по числу деталей).
Получится `qty_total` отдельных партий по 1 шт.
