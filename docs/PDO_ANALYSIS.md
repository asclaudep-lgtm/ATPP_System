## 2. Реальные участники процесса

| Роль | Отдел | Что делает |
|---|---|---|
| **ПЭУ** | Планово-экономическое управление | Принимает заказ, присваивает номер заявки, распределяет сроки |
| **ОМТС** | Отдел материально-технического снабжения | Проверяет наличие материала, заказывает, отправляет служебную записку на проработку |
| **Тех.отдел** | Технологический отдел | Проверяет КД (конструкторскую документацию), определяет материал, даёт тех.указание, оценивает возможность изготовления |
| **Зам.Тех.Дир** | Заместитель технического директора | Утверждает: материал, служебную записку на изготовление |
| **Производство** | Цех | Изготавливает детали по наряд-заданию |
| **Коммерческая дирекция** | Коммерческий отдел | Курирует ОМТС, закупку материала, счета |
| **КДО** | Конструкторский отдел | Срок ответа по конструкторской документации |

## 3. Реальный сквозной процесс (из Журнала заказа и изготовления АТИ)

### Этап 1: Приём заказа (ПЭУ)
```
1. Поступает заявка от заказчика (ОАО "224 ЛО", ПАО "Ил", Росгвардия и др.)
2. ПЭУ присваивает № заявки
3. Определяет: тип ВС (Ту-204-300, Ил-76МД...), объём работ
4. Заполняется строка в «Журнале заказа и изготовления АТИ»
```

### Этап 2: Проработка ОМТС (Снабжение)
```
1. ОМТС получает заявку
2. Проверяет наличие материала на складе
3. Выпускает «Служебную записку на проработку» (например, «250У от 27.07.2023г.»)
   У = Указание, П = Приказ
4. Если материала нет — запускает закупку (счёт, срок поставки)
```

### Этап 3: Технический отдел (Технолог)
```
1. Получает номенклатуру к изготовлению (обозначение, наименование, кол-во)
2. Проверяет КД — наличие конструкторской документации
3. Определяет материал (например: «Пруток Д16чТ кр24-Н ОСТ1 90395-91»)
4. Выпускает «Тех.указание» — технологические инструкции
5. Оценивает «Возм.изготовл.» — возможно ли изготовление (+ / -)
   Пример отказа: «Штамповки, изготовить не можем» (заявка №3, заглушки)
```

### Этап 4: Утверждение (Зам.Тех.Дир)
```
1. Проверяет заключение тех.отдела
2. Подтверждает наличие материала
3. Выпускает «Служебную записку на изготовление» (например, «356п от 03.08.2023г.»)
   Это КЛЮЧЕВОЙ документ — разрешение на запуск в производство
4. Проверяет соответствие ФАП-285 / МинПромТорг (регуляторные требования)
```

### Этап 5: Снабжение материалом (ОМТС + Коммерческая дирекция)
```
1. ОМТС заказывает материал (если ещё не заказан)
2. Отслеживает: счёт оплачен, срок поставки
3. Коммерческая дирекция контролирует бюджет
```

### Этап 6: Производство (Цех)
```
1. Получает служебную записку на изготовление
2. Получает КД и тех.указание от тех.отдела
3. Получает материал от ОМТС
4. Изготавливает детали по наряд-заданию
5. Отчитывается о выполнении
```

## 4. Ключевые документы (реальные)

| Документ | Кто выпускает | Назначение |
|---|---|---|
| **Заявка** | Заказчик → ПЭУ | Входящий заказ на работы |
| **Служебная записка на проработку** | ОМТС | Запрос на проверку возможности изготовления |
| **Тех.указание** | Тех.отдел | Технологические инструкции по изготовлению |
| **Служебная записка на изготовление** | Зам.Тех.Дир | **Главный разрешительный документ** — санкционирует запуск в производство |
| **Наряд-задание** | ПЭУ / Производство | Задание цеху на изготовление конкретных деталей |
| **Счёт** | Коммерческая дирекция | Финансовый документ на закупку материала |

## 5. Главный журнал — структура колонок

Из файла `Журнал заказа и изготовления АТИ.xlsx`:

```
Блок «Заказ»:
  № Заявки | Объем работ | Тип ВС | Служебная записка ОМТС

Блок «Номенклатура к изготовлению»:
  Обозначение | Наименование | Кол-во, шт.

Блок «Производство»:
  Тех.отдел: КД | Материал | Тех.указание | Возм.изготовл.
  Зам.Тех.Дир: Материал | Служебная записка на изготовление
  Регулятор: ФАП-285 / МинПромТорг

Блок «Коммерческая дирекция»:
  ОМТС | Материал
```

**Важно:** колонка «Возм.изготовл.» (возможность изготовления) — это БИНАРНЫЙ флаг (+/−). Если «−» — процесс останавливается. Пример: «Штамповки, изготовить не можем».

                                                       │
                                          ┌────────────┴────────────┐
                                          ↓                         ↓

                                          │
                                          ↓

## 7. Что нужно переделать в ATPP PDO-модуле

Текущий модуль основан на абстрактных предположениях. Реальный процесс
сложнее и включает ОМТС (снабжение) как равноправного участника.

| # | Изменение |
|---|---|
| 1 | Добавить модель `ServiceMemo` (служебная записка) — двух типов: «У» (указание) и «П» (приказ) |
| 2 | Добавить модель `NomenclatureItem` — строка номенклатуры: обозначение, наименование, кол-во |
| 3 | В `ProductionOrder` добавить поля: `aircraft_type` (тип ВС), `omts_memo` (записка ОМТС), `tech_feasible` (возм.изготовл.), `deputy_approved` (утв. зам.тех.дир.) |
| 4 | В Kanban добавить колонки: «ОМТС — проработка», «Тех.отдел — проверка КД», «Зам.Тех.Дир — утверждение» |
| 5 | Интегрировать `MaterialBatch` (уже есть в БД!) — проверка наличия материала |
| 6 | Генератор «Служебной записки на изготовление» в PDF (взамен МТП) |
| 7 | Связать с существующими `WorkOrder` (наряд-задание) |
| 8 | Добавить дашборд по типам ВС: Ту-204-300 (64038), Ту-204-100 (64043), Ил-76МД и т.д. |

## 8. Итог

Реальный процесс УЗГА — это **4-этапный конвейер согласований** перед тем
как деталь попадёт в производство:

```
ПЭУ (приём) → ОМТС (материал?) → Тех.отдел (КД? возможно?) → Зам.Тех.Дир (утверждение) → Цех
```

Ключевой документ — не МТП, а **Служебная записка на изготовление**
за подписью Зам.Тех.Директора. Именно она санкционирует запуск.

МТП (маршрутно-технологический паспорт) в этом процессе — приложение
к служебной записке, а не самостоятельный документ.

PDO-модуль нужно перестроить с учётом ОМТС и этапа проверки возможности
изготовления — это самое узкое место реального процесса.
