# Развёртывание ATPP в локальной сети

Это пошаговая инструкция администратору. Цель: установить систему на несколько ПК, чтобы все работали с **общей** базой данных без конфликтов и с защитой от потери данных.

> Если делаете установку впервые — пройдите от начала до конца. Если что-то уже сделано — пропустите соответствующие шаги.

---

## Архитектура (коротко)

- Один ПК назначается **сервером**. На нём ставится PostgreSQL и расшаривается папка для бэкапов.
- Остальные ПК — **клиенты**. На них ставится ATPP и прописывается строка подключения к серверу.
- Бэкапы делаются:
  - на сервере — ежедневно по расписанию;
  - на каждом клиенте — при запуске приложения, локально + копия зеркалится на сервер;
  - при потере сервера — восстановление из бэкапа любого клиента.

```
              ┌─────────────────────────────────────────────────┐
              │  СЕРВЕР                                         │
              │  - PostgreSQL (TCP 5432)                        │
              │  - БД atpp                                      │
              │  - SMB-шара \\SERVER\ATPP_Backups\              │
              │  - Task Scheduler: ATPP_DailyBackup             │
              └────────────┬────────────────────────────────────┘
                           │ LAN (TCP 5432 + SMB)
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
   ┌────────┐         ┌────────┐         ┌────────┐
   │ ПК-1   │         │ ПК-2   │         │ ПК-N   │
   │ ATPP   │         │ ATPP   │         │ ATPP   │
   └────────┘         └────────┘         └────────┘
```

## Часть A. Настройка сервера

Делается **один раз**, на одном ПК с Windows 10/11/Server.

### A.1. Требования

- Windows 10/11/Server, права Администратора.
- Постоянный IP в LAN (рекомендуется зарезервировать в DHCP). Дальше используем пример **`192.168.1.10`**.
- ≥ 5 ГБ свободного места под БД и бэкапы.
- LAN-подсеть, например `192.168.1.0/24`.

### A.2. Скопируйте проект на сервер

Распакуйте архив `ATPP_System` в, например, `C:\ATPP_System\`.

### A.3. Заполните `scripts/deploy/server_config.ini`

Откройте файл и замените значения под вашу сеть:

```ini
[server]
ServerHost          = 192.168.1.10
LanCIDR             = 192.168.1.0/24

[postgresql]
Version             = 16
PostgresPassword    = РодительскийПарольПостгрес!  # для суперпользователя postgres
AppDb               = atpp
AppUser             = atpp
AppPassword         = ПарольПриложения!            # пойдёт в db.cfg клиентов

[backup]
BackupDir           = D:\ATPP_Backups
ShareName           = ATPP_Backups
KeepDaily           = 30
DailyTime           = 23:00
```

> Пароли придумайте **сложные** (12+ символов, разные регистры и спецсимволы).
> Сохраните их в надёжном месте (Bitwarden / KeePass / 1Password).

### A.4. Запустите развёртывание

PowerShell **от имени Администратора**:

```powershell
cd C:\ATPP_System\scripts\deploy
powershell -ExecutionPolicy Bypass -File .\setup_server.ps1
```

Скрипт:

1. Если PostgreSQL ещё не установлен — попытается поставить его через Chocolatey. Если Chocolatey нет — попросит поставить вручную с https://www.postgresql.org/download/windows/ и запустить скрипт ещё раз.
2. Создаст БД `atpp` и пользователя `atpp` (или обновит пароль).
3. Включит `listen_addresses = '*'` и добавит правило в `pg_hba.conf` (доступ только из LAN).
4. Откроет порт **5432** в брандмауэре Windows для профилей Domain/Private.
5. Создаст папку `D:\ATPP_Backups`, расшарит её как `\\SERVER\ATPP_Backups` с правом записи для аутентифицированных пользователей.
6. Зарегистрирует задачу `ATPP_DailyBackup` в Task Scheduler и сделает первый тестовый бэкап.

### A.5. Проверка

```powershell
# Бэкап лежит на месте?
dir D:\ATPP_Backups\server\atpp_*.dump

# С сервера:
psql -h 127.0.0.1 -U atpp -d atpp -c "select 1;"
```

С другой машины в LAN (если уже доступна):

```powershell
Test-NetConnection -ComputerName 192.168.1.10 -Port 5432
# должно вернуть TcpTestSucceeded : True
```

## Часть B. Настройка клиентского ПК

Повторите для **каждого** ПК пользователя.

### B.1. Установите Python 3.11+

https://www.python.org/downloads/ — при установке поставьте галку **Add Python to PATH**.

### B.2. Опционально — установите PostgreSQL Client Tools

Они нужны клиенту для **локальных бэкапов** (приложение зовёт `pg_dump` при запуске). На странице https://www.postgresql.org/download/windows/ скачайте установщик той же версии, что и сервер, и в мастере **снимите галку Server**, оставьте только **Command Line Tools**. Перезайдите в Windows, чтобы PATH подхватился.

> Если Client Tools не поставить — приложение всё равно работает, просто не делает свой локальный бэкап. На серверный это не влияет.

### B.3. Скопируйте проект и установите зависимости

```bat
cd C:\Users\Public\ATPP_System
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### B.4. Пропишите подключение к серверу

```powershell
cd C:\Users\Public\ATPP_System\scripts\deploy
powershell -ExecutionPolicy Bypass -File .\setup_client.ps1 `
    -ServerHost 192.168.1.10 `
    -AppPassword 'ПарольПриложения!'
```

(если другой пользователь/БД — добавьте `-AppUser ...` `-AppDb ...`).

Что произойдёт:

- В `data\db.cfg` запишется строка подключения к серверу.
- В `data\backup.cfg` запишется UNC-путь `\\192.168.1.10\ATPP_Backups` (туда зеркалятся бэкапы клиента).
- Скрипт проверит, что порт 5432 на сервере отвечает.

### B.5. Запустите приложение

```bat
cd C:\Users\Public\ATPP_System
venv\Scripts\activate
python main.py
```

В строке состояния внизу справа увидите **`БД: postgres @ 192.168.1.10/atpp`** (зелёным). Это значит — подключение к серверу установлено.

Логин по умолчанию: `admin` / `admin` (после первого входа смените пароль через **Сервис → Управление пользователями**).

## Часть C. Что происходит автоматически

| Когда                       | Что                                                    | Куда                                                         |
|-----------------------------|--------------------------------------------------------|--------------------------------------------------------------|
| Каждый день в 23:00 (сервер)| `pg_dump` всей БД                                      | `D:\ATPP_Backups\server\atpp_server_*.dump`                  |
| При запуске ATPP (клиент)   | `pg_dump` (один раз в день на этом ПК)                 | `data\backups\atpp_<имяПК>_*.dump` локально на клиенте       |
| После клиентского бэкапа    | копия в зеркальную папку                               | `\\192.168.1.10\ATPP_Backups\<имяПК>\atpp_*.dump`            |
| Ротация                     | оставляем 30 дневных + понедельники за год             | автоматически                                                |

В меню **Сервис → Информация о резервных копиях...** видны последние локальные копии и состояние сетевого зеркала.

## Часть D. Когда что-то пошло не так

### Клиент пишет «БД: ?» или не подключается

1. На клиенте: `Test-NetConnection -ComputerName <IP сервера> -Port 5432` — должен быть `True`. Если `False` — проверяйте брандмауэр на сервере и LAN.
2. Сравните `data\db.cfg` с тем, что выдал `setup_server.ps1` в конце.
3. На сервере посмотрите лог PostgreSQL: `C:\Program Files\PostgreSQL\16\data\log\` — там обычно сразу видно «password authentication failed» или «no pg_hba.conf entry».

### `pg_dump: command not found` у клиента

Поставьте PostgreSQL Client Tools (см. **B.2**) или просто игнорируйте — клиентский бэкап опционален; серверный делается всё равно.

### Сетевая папка временно недоступна

Это нормально. Локальный бэкап на клиенте всё равно сделается, в лог попадёт предупреждение «mirror WARN». При следующем удачном запуске копия зеркалится автоматически.

### Утрата сервера (HDD умер, машину украли и т.п.)

См. отдельный документ [`backup_recovery_ru.md`](./backup_recovery_ru.md).

## Часть E. Безопасность

- `pg_hba.conf` ограничивает доступ к БД только LAN-подсетью из `server_config.ini`. Из интернета подключиться к 5432 нельзя — порт открыт только для Private/Domain профилей брандмауэра.
- Пароль PostgreSQL хранится:
  - на сервере — в `server_config.ini` (доступ к нему имеет только админ);
  - на клиентах — в `data\db.cfg` (тоже локально, в профиле пользователя).
- В `data\db.cfg` лучше не давать массовый сетевой доступ — это файл локальной машины. В `.gitignore` он уже исключён.
- Восстановление БД из приложения требует роли **admin** (обычные пользователи кнопку «Восстановить» не получат).
- Бэкап-файлы `.dump` тоже содержат данные — не выкладывайте их в публичные облака.

## Часть F. Частые операции

### Как добавить нового сотрудника

В приложении: **Сервис → Управление пользователями → Добавить**. БД одна на всех — пользователь сразу появится у всех.

### Как поменять IP сервера

1. На сервере: правьте `server_config.ini`, перерегистрируйте задачу — но проще оставить старый IP.
2. На каждом клиенте перезапустите `setup_client.ps1` с новым `-ServerHost`. Заодно обновится `data\backup.cfg`.

### Как сделать бэкап «прямо сейчас»

В клиенте: **Сервис → Резервная копия БД сейчас** (или горячая клавиша `Ctrl+Shift+B`). На сервере вручную: `powershell -ExecutionPolicy Bypass -File .\backup_server.ps1`.

### Как проверить, что бэкапы реально живые

В клиенте: **Сервис → Информация о резервных копиях...** — увидите последние файлы и доступность зеркала.
